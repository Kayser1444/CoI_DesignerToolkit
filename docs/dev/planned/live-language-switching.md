# Live language preview feasibility

Investigated 2026-10-04. Status: source-based feasibility investigation; no implementation or in-game validation. Game source inspected reports Captain of Industry 0.8.7d, build 619. Recheck these internals against the installed game before implementation.

## Verdict

A useful live **mod translation preview** is feasible with targeted additions to AutoHelpers (AH) and BDT. It should initially refresh participating mods' UI strings and explicitly registered UI surfaces. Arbitrary live game-wide language switching is not supported by the inspected public game API, and rebinding static strings alone cannot refresh every existing UI or prototype value.

The practical first milestone is a BDT developer panel with target mod, preview locale, apply, reload translation files, and restore controls. This is a proposal, not an existing feature. Preview should be session-only; the normal language preference should remain the startup language.

## What the source establishes

| Area | Evidence and implication |
| --- | --- |
| Normal game language selection | [LocalizationSettings](../../../../../Mafi/Mafi.Unity/Mafi/Unity/InputControl/GameMenu/LocalizationSettings.cs) saves `UserInterfaceLanguage` through `SetNewLangIndex`; `ApplyCurrentLanguage` loads files at startup and returns early for English. [VideoTab](../../../../../Mafi/Mafi.Unity/Mafi/Unity/InputControl/GameMenu/Settings/VideoTab.cs) labels language selection with the restart-required suffix. Calling the normal setting setter does not apply live translations. |
| Public translation loading | [LocalizationManager.TryLoadTranslationsFrom](../../../../../Mafi/Mafi/Mafi/Localization/LocalizationManager.cs) rejects loading once `s_enUsData` contains registered strings. A running game has already registered them. It manages translated data, culture and plural rules, but provides no supported live replacement transaction in this source. |
| Stored strings | [LocStr](../../../../../Mafi/Mafi/Mafi/Localization/LocStr.cs) is a readonly value type containing `TranslatedString`; conversion to `LocStrFormatted` captures that string. Updating the dictionary does not mutate existing copies. [Proto.Str](../../../../../Mafi/Mafi.Core/Mafi/Core/Prototypes/Proto.cs) stores readonly instance `Name` and `DescShort` values. Mod building/product names already captured in prototypes need a separate adapter; static-field rebinding does not cover them. |
| AH's existing mechanism | [ModTranslations](../../../../CoI_AutoHelpers/src/CoI.AutoHelpers/Localization/ModTranslations.cs) selects the active game culture, loads a matching bundle, upserts and rebinds a specified assembly. [CoILocalizationRuntimeAdapter](../../../../CoI_AutoHelpers/src/CoI.AutoHelpers/Localization/CoILocalizationRuntimeAdapter.cs) accesses private game `s_data` by reflection and supports multiple `LocStr` forms. Readonly writes can fail and are reported. The reflection scan reads static fields and may trigger unrelated static constructors; explicit localization-type registration or a narrow scope filter is preferable to broad assembly scanning during preview. This is useful existing machinery, with game-version compatibility risk. |
| Repeated switches | `ModTranslations.Apply` skips English entirely; the adapter skips fields absent from the target bundle. Therefore a naive second apply can retain previous-language values. Fallbacks derived from current fields can already be translated. English restoration and incomplete-bundle handling require a stable source baseline, not a snapshot of whatever locale happened to be active. |
| Deferred refresh | [LaterTextExtensions](../../../../CoI_AutoHelpers/src/CoI.AutoHelpers/Localization/LaterTextExtensions.cs) provides a manually enqueued, one-shot action queue. It does not track labels, subscribe to language changes, or automatically recreate UI. Callback failures are swallowed. A preview service needs explicit refresh registration and useful diagnostics. |
| Current BDT integration | [BDT.Mod](../../../src/BDT.Mod.cs) applies localization during initialization and renderer initialization, then refreshes registered keybind localizations. It has no language-change observer. [BDT.Settings](../../../src/BDT.Settings.cs) captures localized tab names and creates formatted UI strings in its builder. Existing panels need setters or recreation. |
| Settings refresh | [ModSettingsWindow](../../../../CoI_AutoHelpers/src/CoI.AutoHelpers/Settings/ModSettingsWindow.cs) can rebuild tab content. However [ModSettingsHostMb.RegisterTab](../../../../CoI_AutoHelpers/src/CoI.AutoHelpers/Settings/ModSettingsHostMb.cs) identifies a tab by `ModId` plus translated `Title.Value`: registering a differently translated title can leave the old tab and create a duplicate. A stable untranslated tab identity/upsert mechanism is needed. The window's own title is constructed separately. |
| UI reload | [UiHotReloader](../../../../../Mafi/Mafi.Unity/Mafi/Unity/UiHotReloader.cs) accepts a replacement assembly and rebuilds registered dependencies. It is an assembly reload mechanism, not a locale refresh API; it also cannot fix static/prototype strings that were already captured. |
| Locale beyond words | [LocalizationManager](../../../../../Mafi/Mafi/Mafi/Localization/LocalizationManager.cs) separates explicit player-facing `CurrentCultureInfo` from invariant thread culture. [UiComponentFontExtensions](../../../../../Mafi/Mafi.Unity/Mafi/Unity/UiToolkit/Component/UiComponentFontExtensions.cs) and class extensions inspect `CurrentLangInfo.UsesSymbols` when applying styles. A mod-only textual preview does not automatically reproduce target-language numeric formatting or symbol-specific styling. |

## Recommended implementation boundary

1. Add an explicit preview-locale input to AH instead of temporarily changing global `CurrentLangInfo`. Preload and validate the requested bundle before any writes. Preserve registered English source strings/placeholders and original dictionary entries so restoration is deterministic, including a session that started in Swedish.
2. Resolve every owned key from target locale plus English fallback. Apply that complete owned-key set, rather than accumulating target bundles. Restore the original session state on request and unload. Treat missing and malformed bundles as reported failures, retaining the prior preview rather than leaving a partial switch.
3. Handle plurals deliberately. Current AH plural rebinding calls `Loc.Str` and ultimately uses the game's global current plural rules. A Swedish-started session previewing Russian cannot safely use that path unchanged. Construct target-locale plural values with correct rules through a version-checked adapter, or explicitly exclude plural preview until that is supported. Formatted strings and placeholder validation also require coverage.
4. Register per-mod refresh callbacks for settings content, toolbar/tooltips, keybind descriptors and developer windows. Use stable tab IDs and rebuild affected UI on the Unity/UI thread after text rebinding. Track callback failures and show counts of refreshed, missing and unsupported surfaces. A close/reopen instruction is reasonable where a panel is rebuilt on opening; it is insufficient where the panel object persists with captured values.
5. Keep the first implementation limited to BDT plus opt-in maintained mods. AH is a compile-time source library embedded in consumers, not a shared runtime singleton ([workspace workflow](../../../../.github/instructions/coi-maintained-mods/workspace-workflow.md)). Cross-assembly coordination therefore needs a small versioned participant contract or explicit discovery/bridge; one assembly's AH static state cannot automatically control every other copy. Unrelated mods may neither expose rebinding nor refresh callbacks.
6. Treat prototype names/descriptions as a later opt-in feature. Require an adapter specific to the mod and prototype type, preserving IDs and gameplay state. Do not promise arbitrary entity translation testing from the UI-only milestone.

The mod-only preview gives practical translation-layout feedback, while vanilla labels remain at the startup language. Show this limitation in the developer panel. Chinese and other symbol-language previews need glyph/style validation; numeric/date/plural fidelity should be separately stated, not implied by translated text.

## Possible later experimental game-wide mode

Changing the whole session would require bypassing startup guards/private state, replacing global culture/plural information, correctly restoring English, reapplying every participating mod's bundle after replacing vanilla data, rebinding vanilla fields and captured prototype strings, and rebuilding affected UI. The inspected sources establish these obstacles, not a working solution. A separate experimental investigation is warranted only after the mod-preview milestone demonstrates sufficient value. Do not use `EnableLocalization` or clear global registries as a casual workaround: registered English metadata and fallback behavior must survive.

## Manual validation for a prototype

- Start in English, switch BDT preview to Swedish, switch to Russian, and restore; repeat from a Swedish-started game. Verify original session language and settings preference survive restore and restart.
- Exercise settings, toolbar labels/tooltips, keybind descriptors and a persistent developer window both open and closed. Repeat switches and ensure tab counts, callbacks and UI objects do not accumulate.
- Edit a translation JSON on disk and reload the same preview locale. Test missing keys, removed keys, absent locale, invalid JSON and invalid placeholders; verify diagnostics and deterministic English fallback or atomic failure.
- Test singular/plural values at 0, 1, 2, 5 and 21 in Russian. Verify the preview uses Russian rules independently of startup language before claiming plural support.
- Test long German text and Chinese glyphs/layout. Document culture/style gaps if retaining the startup culture.
- Load BDT plus ATD/AFD/KPIE participants and an unrelated non-participant. Verify ownership isolation, shared AH settings labels, restore behavior, and that unsupported mods are identified accurately.
- Inspect a mod building/product name and description. It should be reported outside initial scope until a prototype adapter is validated.
- Change worlds and unload/reload participant UI; confirm preview registration lifetime and restoration. Save/reload a disposable session to verify no preview state or gameplay changes enter save data.

No build was required for this documentation-only investigation. Runtime feasibility remains to be proven with the above bounded prototype.
