# Persist the scope of regular removal orders

BDT persists each active regular removal order as an entity ID, prototype ID, and remaining quantity per product. On restoration, removal is capped to the lesser of current and persisted quantity; missing quantity is considered fulfilled and is never awaited. This preserves one-shot semantics across saves while BDT remains present without turning an old order into a standing request for future products. If a save is loaded and re-saved while BDT is absent, vanilla purges or resets BDT's mod-config cache; reinstalling BDT therefore starts from global defaults and does not restore the old order.
